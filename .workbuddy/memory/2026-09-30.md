## 追加：公共 API 第一个词必须是模块名（用户当天补充的规则）

用户指出 `zynq_clock.h` 违反了这条：同一头文件里 `clock_freqs_get` 用 `clk_`，三个 FCLK 接口却是 `fclk_`。
全工程排查结论：只有这一处违规，其余头文件各自的公共 API 已经是单一模块词
（`gpio_`/`mio_`、`uart_`、`irq_`、`tick_`、`board_`、`fpga_`、`soc_`）。

改法：`fclk_config / fclk_enable / fclk_freq_get` → **`clock_fclk_config / clock_fclk_enable / clock_fclk_freq_get`**
（模块词 `clk`，对象词 `fclk`），与 `enum fclk` / `FCLK0..3` / `FCLK_SRC_*` 保持同一套词汇，
也和同文件的 `clock_freqs_get` 对齐。改动点：`zynq_clock.c/h`、`board.c`、`board_fpga.h` 注释、
README、本项目记忆（含 2026-09-29.md 的历史正文：那里是历史记录，只在名字上同步，不动内容）。

边界（本次定的）：

- 只强制在**公共 API**（头文件里对外可见的函数）上；`static` 辅助函数不加模块词
  ——作用域只在文件内，模块由文件名给出。所以 `zynq_clock.c` 里 `pll_freq_from_ctrl` /
  `periph_ref_freq` / `fclk_reg` 这些 static 保持原样（若日后想连 static 一起统一，再说）。
- 跨文件可见的宏沿用同一模块词习惯：`GPIO_PIN_COUNT`、`MIO_PIN_COUNT`、`FPGA_RESET_LINE_COUNT`、`IRQ_ID_COUNT`、
  `FPGA_IMG_LEN`。
- `mio_*` 与 `gpio_*` 同住 `zynq_gpio.h`，但 MIO pad/pinmux 属 SLCR、是独立一块，故算独立模块词（README 表里已写明）。
- 类型名（`enum fclk` / `struct clock_freqs` / `enum pl_status`）不背模块词，它们是名词不是动作。

验证：改名后全量构建 0 warning，产物尺寸与基线一致（`RAM 6608 B` / `FLASH 102616 B` / BootROM 头 OK）。

按这条规则把全工程重新对齐（一个文件一个模块词，词取自文件名；对不上就改文件名）：

| 做了什么 | 前 | 后 | 理由 |
|---|---|---|---|
| clock 模块词 | `clk_freqs_get` / `clk_fclk_config` / `clk_fclk_enable` / `clk_fclk_freq_get`、`struct clk_freqs` | `clock_freqs_get` / `clock_fclk_config` / `clock_fclk_enable` / `clock_fclk_freq_get`、`struct clock_freqs` | 文件名是 `zynq_clock`，模块词就该是 `clock`，没有理由缩写 |
| gpio 拆文件 | `zynq_gpio.c/h` 里混着 `gpio_*` 与 `mio_*` 两套 API | `zynq_gpio.c/h`（`gpio_*`）+ **新增 `zynq_mio.c/h`（`mio_*`）** | MIO pad 属 SLCR，与 GPIO 控制器是两个硬件块；一个文件只许一个模块词。GPIO 保留在原名文件里（用户给的另一选项是"文件名改成 mio"，但那会让 `gpio_*` 变成无家可归的一方） |
| MIO 宏 | `GPIO_MIO24_GPIO`、`GPIO_FN_UART`、`GPIO_MIO0_LVL` | `MIO24_GPIO`、`MIO_FN_UART`、`MIO_BANK0_LVL` | 宏属于 MIO 模块，首词跟着模块走；生成器 `gen_mio_macros.py` 同步改为 `MIO<pin>_<功能>`，输出与 `zynq_mio.h` 里的宏块逐 token 一致 |
| system 文件 | `zynq_system.c`（里面是 `soc_init`） | `zynq_soc.c` | 文件与模块词对不上时改文件名（用户定的方向），函数名 `soc_init` 不动——它在 README/启动汇编/记忆里都是"启动入口" |

同时对齐的边角：`source/driver/CMakeLists.txt` 加 `zynq_mio.c`；`source/soc/CMakeLists.txt` 改 `zynq_soc.c`；
`board.h` 增 `#include "zynq_mio.h"`（main.c 经它用 `mio_*`）；`zynq_cmsis.h` 注释里的 `zynq_system.c` 引用同步；
README 的源码结构 + 模块词表重写；`boot_analysis.md` 里的文件路径全改 `zynq_soc.c`。

**验证**：全量构建 0 warning，产物与基线完全一致（`RAM 6608 B`、`FLASH 102616 B`、BootROM 头 OK）——
拆文件没有引入任何代码差异（`.text` 布局都相同）。头文件模块词扫描结果：每个自有头文件恰好一个模块词
（`board`/`fpga`/`gpio`/`mio`/`uart`/`clock`/`irq`/`tick`，`board_fpga_bitstream.h` 与 `zynq_common.h` 只有类型和宏）。

**踩坑（写给以后写脚本的自己）**：用 Python 批量写 C 文件时，如果先把内容按 LF 拼好、再用
`open(..., newline='CRLF')` 写，而源文本里本来已经带了 CR（例如从 CRLF 文件读进来时没做 universal-newline 归一），
就会写出 CR CR LF 三个字节：`grep`/`wc` 看着正常，GCC 却把那个孤立的 CR 也当换行，报错行号翻倍
（730 行的头文件被报成 1460 行），极难定位。教训：读写一律走 universal newlines——读用
`open(p, encoding='utf-8')`（自动把 CRLF 归一成 LF），写的时候才指定换行符；改完自检：
文件里不应出现连续两个 CR。

## 追加第四轮：模块定名 mio，文件 zynq_mio（最终形态）

用户在"合成一个"之后追加：**模块名改成 mio，文件名改成 zynq_mio**。至此 PS 引脚域收敛为一个模块：
