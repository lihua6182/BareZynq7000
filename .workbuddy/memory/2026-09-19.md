## 14:30 QSPI时序分析：clock_init中PLL修改是否影响QSPI
结论：不会。原因链：
- clock_init 改 ARM/IO PLL 均严格走 UG585 ch.25 软件PLL更新序列：先 force bypass(行220/254) 再改FDIV/assert reset/de-assert/wait lock/leave bypass。bypass 期间 PLL 输出被无缝替换为 PS_CLK(参考输入)，PLL_RESET 是在 bypass 下置位，输出不变 => QSPI 参考时钟始终为有效的 PS_CLK，不停止、不毛刺。
- QSPI 为边沿计数(SPI flash 只读有效边沿数)，CS 保持期间时钟频率跳变/暂停均可恢复，不会错位；真正致错的是 SCLK 毛刺(同沿多沿)，而 bypass 多路复用是 glitch-free，不产生毛刺。
- QSPI 时钟源在 clock_init 期间仍是 BootROM 交接值(代码注释行264-265 称 ARM PLL/40)；IO PLL 重配时 QSPI 根本不在 IO PLL 上 => 零影响。切到 IO PLL 的动作只在 qspi_clock_init(行274)做，且此时已 LQ_MODE=0(行131)退出线性模式，再写 LQSPI_CLK_CTRL(行149-150)+脉冲 reset(161-163) => 切换安全。
- clock_init 自身在 XIP 执行，但依赖 I-cache(行200-203)，bypass 时钟有效故 cache miss 仅变慢不致命。
=> 顺序正确，无需把 PLL 修改移到 qspi_clock_init 之后。唯一会破坏安全性的改动是删除 force bypass 这一步。

## 15:19 J-Link 诊断：②③ 导致起不来，已还原
用 JLink.exe (V9.56, S/N 600107328) 连 XC7Z010 读状态：
- SCTRL: MMU disabled / L1 I&D cache disabled / BP disabled => 卡在 mmu_enable 之前。
- PC=0xFC000E08(flash XIP), R1=0x8000016B(LQSPI_CR), R2=1(QSPI.ER), R3=0xE000D000(QSPI base) => 卡在 clock_init 内 qspi_clock_init() 返回后。

已还原 ②(ACTLR 预取) + ③(重排)，恢复 mmu_init->mmu_enable->clock_init。-fsyntax-only 通过(EXIT=0)。
结论：① L2 XIP 不能走"先重配时钟再开 L2"，须保证 QSPI 重配窗口 CPU 不从 flash 裸取指；或先开 L2 再重配(但重配期仍需 OCM 执行)。
