- 硬件事实（重要）：Zynq-7000 的 PCAP 数据在硬件上只能经 DevC/PCAP bridge 的 DMA 引擎（UG585 图 6-16，APB 无数据 FIFO；ROM_SHADOW 是安全用 write-once 寄存器不是 FIFO）。
  故"手动写入"的可行形态 = CPU 逐块排队 DMA + 轮询 DMA_DONE，块大小由调用方给（默认 4 KB）。已向用户说明。
- 新增 source/soc/zynq_devcfg.c/.h，严格按 UG585 ch.6 "Configure the PL via PCAP Bridge Example" 11 步 + ch.2 电平转换序列（LVL_SHFTR_EN 0x0A→配置→0x0F）：

  toggle PCFG_PROG_B(bit30) 做 PL housecleaning → 等 STATUS[PCFG_INIT] → 检查 DMA_CMD_Q_F → MCTRL PCAP_LPBK=0 →
  分块写 DMA_SRC_ADDR/DMA_DEST_ADDR(0xFFFFFFFF=PCAP)/DMA_SRC_LEN/DMA_DEST_LEN(最后写=触发) → 等 DMA_DONE 并 ack →

## 19:2x 用户要求"改成 DMA 实现"→ 一次性 DMA 整块传输（已构建通过）

用户翻案：不要 CPU 分块喂数据，改成真正的 DMA（一次命令搬完整帧）。
- 关键依据（写进代码注释了）：UG585 ch.6 PCAP 示例 **step 8c/8d 原文就是 "Total number of 32-bit words in the new PL bitstream"**，
  即官方就是"一条 DMA 命令搬整帧"，FSBL 与 U-Boot `drivers/fpga/zynqpl.c` 也都是这么写（dma_src_len = dma_dst_len = bsize/4，dest=0xFFFFFFFF）。
- 对 4KB 规则的正确理解（上一版过度解读了）："DMA transactions must be 64-byte aligned to prevent accidently crossing a 4K byte boundary"——
  **64B 对齐是手段、不是额外约束**：源地址 64B 对齐 → DMA 内部发 64B burst → 4KB 是 64 的整数倍 → 不可能跨页。故整帧单命令合法。
- 改动：
  1. `zynq_devcfg_load(const void*, uint32_t bytes)` —— **删掉第三个参数 chunk_bytes**，删除分块 while 循环；
     DMA_SRC_ADDR/DEST_ADDR(0xFFFFFFFF)/SRC_LEN/DEST_LEN 只写一次（反汇编确认只有 4 条 str，dsb 在 DEST_LEN 前）。
  2. 完成等待：仍轮询 `INT_STS`（UG585 说 DMA_DONE 可用中断也可用轮询；轮询让启动路径不依赖 GIC 与 1ms tick，避免 WFI 挂死风险）。
     DMA 等待上限拆成 `DEVCFG_INIT_POLL_LIMIT 8e6`（PL 上电 ~1s）与 `DEVCFG_DMA_POLL_LIMIT 6e7`（DMA 安全网 ~10s）。
  3. 传输错误提前返回：等待循环内同时查 `DEVCFG_XFER_ERR_Msk`，一旦出错立即 ack 并返回，不再傻等。
  4. 新增错误码 `ZYNQ_DEVCFG_ERR_DMA_TIMEOUT`（区分"DMA 出错"与"DMA 没回"），共 8 种。
  5. main.c 调用点改为两参数，注释同步。
- 构建：0 warning，FLASH 仍 2,091,932 B，BootROM 头 OK；`cmp` 确认 bitstream 仍在 0xFC002000 且逐字节一致（2083740 B，64B 对齐、4 的倍数）。
- 未采用中断式完成（IRQ ID#40 + zynq_fiq_isr_40 + WFI）：启动期 CPU 无事可做收益为零，且 WFI 若 FIQ/GIC 未就绪存在挂死风险。若日后需要可再加。

  2. **`CTRL[PCFG_POR_CNT_4K]`(bit29) 显式清 0**：那是"缩短 PL 上电复位时间"的优化位（UG585 ch.6 PL Initialization Time Optimization），清 0 = 走完整 64k POR 定时器。与 SEGGER 一致。

- 新增诊断（SEGGER 没做，UG585 ch.6 "Determine the PL State" 明确写了）：`MCTRL[PCFG_POR_B]`(bit8)=0 → 新错误码 `ZYNQ_DEVCFG_ERR_PL_NO_POWER`，
  把"PL 没供电"与"PCFG_INIT 超时"区分开，方便上板定位。
- 新增位定义：`DEVCFG_STATUS_DMA_DONE_CNT`(29:28)、`DEVCFG_MCTRL_PCFG_POR_B`(8)。错误码共 9 种。
- **故意不跟** SEGGER 的两点：
  - SEGGER 一开始就 `LVL_SHFTR_EN = 0x0F`（双向全开）；我按 UG585 ch.2 保持 0x0A → 配置完 → 0x0F，避免 PL 未配置时向 PS 灌未定态信号。

  本项目 bitstream 在 0xFC002000（64B 对齐、只读、CPU 从不写 → 无脏 cache line），无需 bounce buffer 与 cache clean。
