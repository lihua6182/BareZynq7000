### 我错在哪（推理错误，不是实现 bug）

我用"`fpga_load` 运行期能连续读 ~156KB"论证"重配后线性口可靠"——**这个证据
是循环论证**：

- `fpga_img` 在 flash `0xFC00C000`，106,156 B，LZMA 解码要把它**当数据流读**。
- 但**预热已经把整个镜像灌进了 L2**。所以运行期那些"连续读"绝大多数是
  **L2 命中，根本没走 QSPI 总线**。
- 我把"数据能在 L2 命中时读出来"当成了"重配后的端口能连续读"。**证据无效。**

推论：重配后线性口在 100MHz 下**只有首次/少量访问被验证过**（预热只覆盖到
soc_init 结束），从未验证过"重配后 + 缓存未预热 + 大流量顺序读"。删掉预热正好
把这个未验证路径变成唯一路径 → FPGA 配置失败。

**教训**：`code_notes.md` 里"实测读不可靠"是**上板验证过的负面结论**，不是待证
假设。工程记忆里的负面实测结论优先级高于我从"代码看起来能跑"推出的正面论证。

### 顺带发现（未上板验证，保留备用）

分析 veneer 时发现：`soc_init` 在 flash `0xfc002628`，离 `.fast` 约 4.2GB，超出
`bl` 的 ±32MB 范围 → 编译器为其调用生成 **flash 里的 veneer**（如
`__qspi_reconfig_veneer`）。即"预热保证重配窗口内零 flash 取指"这句话**并不严格
成立**：重配后 `qspi_reconfig` 返回时的 veneer 取指本身就来自 flash，只是恰好
被预热覆盖到了。若将来再动这块，把 `soc_init` 也放 `.fast` 可消除该隐患——
但**这本身也需要上板验证**，别单独改。

另：探测读若要恢复，走**非缓存别名** `0xFB200000`（页表 `table[0xFB2]`→
PA `0xFC000000` non-cache RO），因为走缓存窗口时一次坏样本会被分配进 L1D/L2，
重试永远命中污染行、再不访问总线。`0xFB2` 与 PL/IOP `[0x400,0xFA0)`、flash
`[0xFC0,0xFD0)` 区间均无冲突（已核）。

## 下午：按"其他模型推理不可尽信"原则独立复核"能否删预热"——结论不变，认知细化

1. **失败实验的精确含义**：删预热后 FPGA 配置（~106KB 持续流读）失败，证明的是
   "重配后端口在**持续大流量**下不可靠"，不是"端口全死"。系统运行期 L2 逐出后
   的稀疏 miss 一直走该端口且无碍（30MB/s USB 测试为证）→ 稀疏小流量可用。
   预热真正不可替代的作用：把**启动期持续流**（比特流+LZMA 表）转成 L2 命中。
2. **机理**：SCLK 100MHz + 内部回环 + DLY 保持复位值（MIO8 焊盘环回未启用），
   采样裕度板级相关；边际时序的错误率随读量放大，与"小读过、大读挂"签名吻合。
3. **veneer 隐患比上午记录的要弱**：veneer 在**调用时**（重配前、BootROM 配置下）
   取指；返回路径回到已被预热/I-cache 覆盖的 soc_init 本体。不构成独立风险。
4. **唯一合法删除路径**（若要）：先把端口做可靠——调 LPBK_DLY_ADJ DLY / 降 SCLK
   （如 50MHz）/ 启用 MIO8 焊盘环回，再用 `0xFB200000` 别名做全镜像 CRC 长时间
   浸泡测试上板验证；通过后预热可缩到只盖重配窗口。收益仅几十 ms 启动时间，
   风险不对称，不建议投入。
5. 部分预热（只盖重配窗口代码）**无效**：失败点在运行期流读，不在窗口内。

## 预热方式自身的可靠性审计

- 假设①（flash 窗口可缓存）**代码级成立**：`table[0xFC0..0xFCF] =
  TT_WRITE_BACK_ALLOC | TT_AP_RO`，L2 在预热前已使能；数据读灌 L1D+L2，
  取指经 L1I miss → 统一 L2 命中。
- 假设②（跨度覆盖全部可取指内容）**当前成立但靠链接顺序巧合**：flash LMA
  顺序 = boot_header → vectors → .text → .rodata → extab/exidx → init/fini
  array → .fast LMA → .data LMA（_sidata），预热终点 `_sidata+SIZEOF(.data)`
  恰好在最后。**无链接期 ASSERT 强制**，日后新增尾部 AT>FLASH 段会静默破
  坏覆盖——唯一实质软肋，建议在 flash_xip.ld 的 ASSERT 区补一条。
- 预热读本身无校验（QSPI 读无 ECC）：单次位错 → 本次启动响亮失败、下次
  重预热恢复，无持久污染，仅可诊断性差。
- 保持性可靠：预热→重配之间只有 sys_clock_init（OCM 执行），L2 512KB vs
  镜像 ~156KB，L2 投机预取已关，中断在重配后才使能（预热期无 ISR 取指竞争）。

## 镜像超过 L2（512KB）时的失效模式与预案（分析，未实施）

- 失效模式：预热是顺序流读，超过 512KB 后**先预热的先被逐出**——而最先读
  的恰是启动代码（重配后返回路径 soc_init 尾/irq/tick 所在低地址），风险
  最大；比特流若不在"最后 ~512KB"内，fpga_load 流读直接压到未验证端口，
  等价于删预热。
- 预案分级：①现在就做：链接期 ASSERT 镜像上限（如 384KB，留 128KB 给运
  行期数据），触线响亮失败；②接近上限：两遍预热——全量一遍后**复刷关键
  区**（镜像头部启动区 + 比特流区间，取数组地址即可定位），使其成为 LRU
  最新；③远超上限：PL310 way lockdown，或重配前把比特流拷到 OCM/RAM
  （192KB RAM 预算紧张，需重新核算 heap/stacks）。
